1. Overview

MT Alchemy is a People Development Consultancy specialising in Emotional Intelligence, Leadership Development, Team Engagement and Workplace Well-being. Its tagline is "We don't just run activities. We shift mindsets, behaviours, and team culture." The platform turns visitors into enquiries, learners and corporate clients, and has four modules.

Corporate website

One landing page whose menu glides to About, Services, Upskilling, Store, Insights and Contact. It also has founders, impact stories, an EQ self-assessment, a "For organisations" enquiry and a cartoon virtual tour reached by QR code.

Learning management system

A course catalogue filtered by each learner's pathway (career stage and interests), purchase and enrolment, a modular player (video, PDF, reading, quiz), progress tracking, and certificates with a public verification link.

E-commerce store

Digital products download after payment; physical products ship with a Processing, Shipped, Delivered timeline. One checkout handles products, courses and employer seats. Payments run in test mode.

Role-based portals

Five roles (Guest, Individual, Employer, Trainer, Super Admin), each with its own navigation, notifications and permissions enforced by database security rules.

2. Information architecture

The site has one public area and four signed-in portals. The menu is available everywhere. On the home page each item glides to its section of the landing page; from any other page it opens the full page.

3. System architecture

The application is one Flutter codebase that talks directly to Firebase. There is no custom server: business rules run in the client stores, and Firestore security rules decide who may read or write each document. The web app is a static site on GitHub Pages that connects to Firebase over HTTPS.

How data flows

  1. On sign-in, AuthStore (listening to Firebase Auth) streams users/{uid} (role, organisation, pathway) and the organisation document.
  2. The other stores listen to AuthStore. When the uid changes they cancel their listeners and subscribe to that user's data, for example enrolments where userId == uid.
  3. Screens watch the stores and rebuild automatically. CatalogStore starts with the bundled catalogue so pages paint instantly and work offline; Firestore then replaces it live.
  4. Checkout, assignment and enrolment use batched writes, and the stock decrement uses a transaction. Lesson progress updates optimistically.
  5. Actions return a readable message, such as "That email and password do not match an account.", instead of throwing.

Routing, role guards and theme

Public pages share AppShell: one Scaffold with a glass AppBar and an end drawer below 1024 px. Signed-in pages share PortalShell: a second Scaffold with its own AppBar, a side rail (a drawer on small screens), the notification bell, a theme toggle and one scroll area. Portal pages are flat sibling routes, because nested child routes would stack a page that Flutter never lays out. The router waits for Firebase to restore the session before deciding, so a signed-in user is not sent to the login screen on refresh.

Colour tokens are static getters on the active palette. When the brightness changes, every element is marked for rebuild so each widget re-reads the tokens; the page, scroll position and widget state survive. The toggle reads the live brightness when pressed, so it always flips.

5. The five user journeys

A · Individual learning

  1. Register and choose a career stage and interest areas (/register).
  2. The catalogue shows only courses that match both (/portal/me/courses).
  3. Buy the course and pay at checkout (test card 4242 4242 4242 4242).
  4. An enrolment is created from the paid order; the dashboard shows progress.
  5. Open the course: watch the video, read the PDF, Mark complete, Next.
  6. Pass the quiz (70% or more) to finish and receive a certificate with a public verification link.

B · Digital product

  1. Store, then the EI Self-Coaching Toolkit.
  2. Add to cart and check out (no delivery address, no shipping).
  3. A payment record is created in test mode.
  4. My downloads, then Download. The count is tracked.

C · Physical product

  1. Store, then Cart (delivery is free from £50 of shipped goods).
  2. Enter a delivery address at checkout and pay.
  3. Stock is reduced in a transaction and a shipment is created as Processing.
  4. The super admin marks it Shipped (with a tracking number), then Delivered; the buyer is notified each time.

D · Employer

  1. Register an organisation (/register?type=organisation).
  2. Add employees; they join automatically when they register with that email.
  3. Buy courses: choose the number of seats and pay.
  4. Assign courses to people; each assignment uses a seat.
  5. Watch the progress report and analytics update live.

E · Corporate enquiry

  1. Open "For organisations" from the landing page or footer.
  2. Submit the enquiry (saved to Firestore).
  3. The super admin inbox tracks it: New, In discussion, Proposal sent, Programme agreed, Closed.
  4. The admin writes the customised programme proposal.

Staff free access

  1. A trainer or admin opens any course free (admin preview, nothing is saved).
  2. Courses, then Students shows enrolled, paid, employer seats and free access.
  3. Search a learner to give free access, or remove someone. A removed payer is not refunded automatically.

The live verification script checks these rules. Users cannot change their own role. Self-registration can only create individual or employer accounts. An enrolment needs a paid order or an assignment. A certificate can be created only when the enrolment is complete. Employers cannot touch another organisation's data, draft courses are hidden from everyone except staff, and buyers cannot mark their own parcel delivered.

Business rules

RuleBehaviour
Learning pathwayA course is open to a learner only if its level suits their career stage and its practice area is one of their interests. Student: Foundation. Professional: Foundation and Practitioner. Manager: Practitioner and Leader. Senior leader: Leader. Other courses stay visible but locked, with the reason. Employer assignments and staff are not restricted.
Pricing and shippingPrices in GBP. Delivery is £4.95, free from £50 of shipped goods. Digital products and courses never ship.
SeatsAn employer buys seats per course (stored on the organisation). Each assignment uses one seat per person and is refused when seats run out.
Progress and certificatesProgress is lessons completed divided by lessons. Quizzes pass at 70% and complete their lesson. Completing every lesson creates the certificate; its code is built from the first three letters of the course id and the start of the learner id.
PaymentsSimulated gateway in test mode. A card number starting 4000 0000 0000 0002 is declined; any other valid test number is approved. Only the last four digits are stored.
Free accessStaff can create an enrolment with source "granted". It needs no order and no seat.
Offline fallbackIf Firestore is unreachable, the bundled catalogue keeps pages working.

7. Design system, imagery and motion

Colour

Pure white (#FFFFFF), a neutral zinc "ash" scale (#F4F4F5 to #18181B) and Crimson Red (#C8102E) as the single accent for calls to action, active states, progress and focus. Grey-to-red gradients appear only at moments of change: a passed quiz, a completed order, a finished course. There is no grain texture. A full dark palette mirrors the light one.

Glassmorphism and type

A shared GlassPanel (backdrop blur, translucent fill, hairline border) is used on the navigation, hero copy, summaries and forms, a few per screen and never nested, with a solid fallback for high contrast. Headings use Fraunces and body text uses Manrope.

Imagery

Thirty free-licence Unsplash photographs, converted to WebP, appear on every course, product, service and article card. Courses and products store an imageUrl that admins can change; the seeded red ink artwork is the fallback. Founder portraits are uploaded from the site.

Motion

The landing film has a floating glass crystal and parallax particles. Content reveals in staggered steps on scroll. Every card lifts on hover with a soft red shadow, a photo zoom and press feedback; service cards also tilt in 3D. Pages change with a fade-and-lift transition, the menu glides to its landing section, EQ result bars animate and impact stories rotate. All of it respects the reduced-motion setting.

Accessibility

Icon buttons have semantic labels, form errors are announced through live regions, focus outlines are visible, the tour film has captions and chart legends spell out their counts.

10. Deployment and operations

TaskHow
Run locallyflutter pub get then flutter run -d chrome
Publish the siteCommit, then bash tools/deploy_pages.sh. It builds with the /mt-alchemy/ base path, copies index.html to 404.html so deep links such as /portal load, adds .nojekyll and pushes the gh-pages branch.
Change rules or indexesEdit firestore.rules or firestore.indexes.json, run firebase deploy --only firestore, wait three minutes, then npm run verify.
Reset demo datacd tools/seed && npm run seed. It exports the catalogue, opens the temporary seed rules, writes 71 documents and redeploys the real rules.
Re-render a videocd video && npm run render:tour (or render:all).
Authorized domainsThe Authentication allow-list holds localhost, *.firebaseapp.com, *.web.app and ajaynagarajan2005.github.io. Add any new domain under Authentication, Settings.

Troubleshooting

SymptomLikely cause and fix
"You do not have permission to do that."A security rule refused the write. Check the role in users/{uid} and reproduce the case in verify.mjs.
Catalogue shows but never updatesFirestore is unreachable and the app is using the bundled catalogue. Look for "Could not reach Cloud Firestore" in the console.
"requires an index"A new compound query. Follow the link in the error or add the index to firestore.indexes.json.
Portal is empty after loginThe profile document is missing. Re-run the seed or create users/{uid} with a role.
QR code opens a blank or wrong addressThe build was made without SITE_BASE. Rebuild with deploy_pages.sh.

11. Limitations and future work

AreaCurrent state and next step
PaymentsSimulated in test mode with no real charge. Next: a payment provider such as Stripe with a server-side webhook, which needs Cloud Functions.
File storageFirebase Storage needs the paid plan, so PDFs and downloads are served from the site's own /downloads folder and founder photos are stored in Firestore as small JPEGs. Next: Storage for lesson videos, PDFs and photos.
EmailFirebase sends password-reset email. Order receipts, employee invitations and enquiry replies appear in the app (notification bell) and are not emailed. Next: transactional email.
CertificatesViewable and verifiable by link; there is no PDF download button yet.
RefundsRemoving a paying student does not refund them. An admin handles that with the payment provider.
DevicesChecked in desktop and phone-sized browsers. Native Android and iOS builds share the code but were not tested on devices.
Browser window fitOne report of the page not filling the window edge to edge on a particular display was not reproduced and remains open.
Hosting deep linksGitHub Pages returns HTTP 404 for deep links before the app loads, then the app renders normally. Firebase Hosting would return 200.
EQ self-assessmentAn engagement tool with ten statements across five areas. It is not a validated psychometric instrument.
Hero videoAn AI-generated landing clip was deferred; the Remotion films are used.

C. Glossary

  • Pathway: a learner's career stage plus interest areas; it decides which courses they can buy.
  • Seat: one employee's place on a course, bought by an employer and used on assignment.
  • Free access (granted): an enrolment created by staff with no payment.
  • Admin preview: staff opening a course without enrolling; nothing is saved.
  • Alchy: the crystal mascot who narrates the tour.
  • Seed: the script that fills Firebase with demo accounts and content.
  • Test mode: payments are simulated and no real card is charged.
